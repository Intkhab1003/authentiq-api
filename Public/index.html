API SPECIFICATION

Endpoint Contract & HTTP Status Codes

Every authentication request is validated sequentially and returns predictable JSON payloads.

200 OK Valid Credentials

Both username and password match the server's .env configuration. Returns session confirmation metadata without echoing the password.

400 BAD REQUEST Missing / Empty Input

Triggered when username or password is omitted, non-string, or blank whitespace after trimming.

401 UNAUTHORIZED Invalid Credentials

Returns a single generic error ("Invalid username or password.") to prevent user enumeration attacks.

SECURITY ARCHITECTURE

Educational Demo vs. Production Authentication

Understanding the boundary between learning prototypes and production security engineering.

What AUTHENTIQ Demonstrates (Week 4 Demo)

  • Secret Isolation: Loads local credentials via dotenv so zero secrets exist in frontend JS or Git history.
  • Strict Input Sanitization: Rejects malformed JSON and empty strings before running comparisons.
  • Zero Password Exposure: Never prints passwords to server logs or returns them in API responses.

What Production Systems Require

  • Cryptographic Hashing: Passwords must be salted and hashed using Argon2id or bcrypt inside a database—never compared in plaintext.
  • Stateful/Signed Sessions: Issuing signed JWTs or encrypted HttpOnly cookies after login.
  • Abuse Protection: HTTPS/TLS encryption, rate limiting, brute-force lockouts, and multi-factor authentication (MFA).
